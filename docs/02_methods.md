# 方法与8组实验定义

## 1. 统一框架

单个集中式控制器同时控制3架UAV。共享全局任务/信道信息和统一系统目标，因此当前使用单智能体，不把3架机拆成独立博弈的飞行智能体。这里的关联博弈用于任务卸载选择，与多智能体强化学习不是一回事。

| 实验ID | 轨迹 | 关联及资源 | 训练 |
|---|---|---|---|
| baseline_priority_greedy | 粗网格加权速率贪心 | 独占时延选节点＋组内均分 | 无 |
| baseline_greedy_solver | 同一贪心 | 本节求解器 | 无 |
| pure_ppo | 原PPO | 同一PPO输出 | 有 |
| hybrid_ppo | 原PPO | 求解器 | 有 |
| hybrid_sac | 原SAC | 求解器 | 有 |
| hybrid_ddpg | 原DDPG | 求解器 | 有 |
| hybrid_ppo_ar_adaptive | 自适应AR＋延续价值PPO | 求解器 | 有 |
| hybrid_ppo_ar05 | AR=0.5＋延续价值PPO | 求解器 | 有 |

混合组Actor输出6维全局坐标速度分量，经tanh映射、向量限速与安全处理得到执行速度。关联与CPU/带宽由求解器决定，不由Actor决定。原混合PPO同样接收上一速度潜变量、当前已知服务成本特征，避免把新增信息差异全部当结构收益。

## 2. 两个贪心基线

每架UAV独立搜索16个方向×3个非零速度(5/10/20m/s)，另加一个悬停，共49个不同候选。用槽首CSI按距离平方比预测候选位置的加权总速率；不做局部细化，评分时不考虑其他UAV位置，也不读取剩余电量或能耗罚项。分机选请求后，环境统一处理边界、速度和防撞。相同分数时优先低速。

Priority Greedy按deadline升序遍历，对每个任务估算本地及可用远端节点的“独占全部带宽/CPU时延”，选择时延最小者。最后按关联人数，在每个远端节点内分别均分带宽和CPU；不扣减剩余资源、不退还余量、不迭代重新关联、不调用KKT。因这一规则下排序不改变最终分配，不能宣称它实现了优先级资源优化；名称沿用实验ID，优先级仍用于轨迹速率评分与最终指标。

Greedy＋Solver共用完全相同的轨迹策略，只将卸载和资源部分替换为求解器。它也不做能量预算规划。停服后两者均排除关闭的UAV，但推进能量继续增加。

## 3. 关联与凸资源分配

### 固定关联

节点j接收集合S_j时，求解

\[
\min_{b_i,f_i>0}\sum_{i\in S_j}w_i
\left[\frac{D_i}{R_{ij}(b_i)}+\frac{C_i}{f_i}+\delta_{ij}\right],
\quad\sum b_i\le B_j,\quad\sum f_i\le F_j,\quad T_i\le d_i.
\]

不含能耗变量。速率R(b)为正凹函数，D/R(b)、C/f及期限约束构成凸子问题。定义期限乘子μ_i≥0、q_i=w_i+μ_i，KKT给出

\[
f_i^*=F_j\frac{\sqrt{q_iC_i}}{\sum_{k\in S_j}\sqrt{q_kC_k}},\qquad
q_i\frac{\partial[D_i/R_{ij}(b_i)]}{\partial b_i}+\lambda_b=0.
\]

无活动期限时μ=0，CPU与√(w_iC_i)成正比；有活动期限时必须协调μ，而不是无条件套用√(wC)。固定总功率香农速率下，带宽没有通用显式闭式解。代码以单调KKT关系、等式约束Newton及活动集/对偶Newton求解；必要时调用凸原问题后备求解，核对可行性和最优性证书。数值未解决、证书不足或期限不可行均显式保留状态。

### 关联选择

令Φ(a)为给定关联a、重新优化节点资源后的共同加权成本。先用可行上一槽关联作暖启动；另一初值从本地执行出发，按优先级修复本地无法按期完成的任务，允许有界双用户重定位。已停服UAV不在候选集合。

随后按优先级逐用户尝试单边迁移，每次重算相关资源组；只有可行且成本证书确认下降超过ε才接受。缓存用户集合的节点解、用下界剪枝减少重复求解，避免遍历5²⁰个关联。

有限关联集合中的严格势函数下降可支持无限制扫描下的有限改进性质，但**本版最多5轮扫描，不保证每槽都得到纳什均衡或全局最优**。只有 `epsilon_equilibrium_certified=true` 时才报告该容差下的单边稳定证书。可行修复失败不等于证明全局不可行；任务和超期不被删除。每轮至多约N(K−1)个迁移候选，K=5；实际费用还包括修复、凸子问题和数值迭代，应看决策墙钟而不是只报候选计数。

## 4. 纯PPO

纯PPO动作146维：6速度、20×5节点偏好、20带宽偏好、20CPU偏好。节点偏好经softmax形成分类分布，按独立键控场景随机数选本地/UAV/卫星；停服节点先屏蔽。带宽与CPU偏好在每个已关联节点内softmax归一化，满足资源总量但不保证期限。全程不调用关联/KKT求解器。

默认评估用连续Actor条件均值；底层分类路由仍按声明的键控随机数选择，不能将其描述为完全确定性argmax卸载。纯PPO的能量可行不代表卸载正确：任务发往极差卫星链路可以产生巨大时延，却几乎不增加UAV计算能量。

## 5. AR＋延续价值改进

只对6维运动潜变量引入时间相关性：

\[
z_t=\rho_tz_{t-1}+(1-\rho_t)\mu_\theta(s_t)
+\sqrt{1-\rho_t^2}\,\sigma_\theta\kappa\epsilon_t,
\quad a_t=\tanh z_t.
\]

固定组ρ=0.5；自适应组每架一个ρ_t=0.9sigmoid(h_θ(s_t))，初始约0.8。上一潜变量进状态，episode初清零；κ是启用降噪后的标准差乘数。PPO似然使用原始高斯样本及条件分布，不对安全投影后的动作伪造密度。

槽首资源结果与当前速度无关，因此混合组在选择速度前已知当前延迟奖励c_t=−5J_t。延迟价值写为c_t＋U(s_t)，U只学习后续延迟价值，最后一槽强制0；罚项价值单独学习。两个分量使用PopArt调整价值拟合尺度，Actor优势仍先按真实奖励单位相加，再统一标准化；没有按分量方差重新定义目标。Critic不读取未来任务表。

两组默认都启用可关闭的降噪与Actor学习率衰减：预算进度10%–70%内κ从1对数线性降至0.1；Actor学习率随预算进度线性降到初值0.2倍，Critic学习率不跟随衰减。调度在rollout边界切换，评估使用检查点实际保存的尺度。

本次是AR、延续价值、PopArt和调度的组合对比。若要分别归因，需额外消融；当前小幅J差异不能直接说明某单项结构普遍优于原PPO。共享代码中的注意力、多网络、纯RL延续价值及TD3等内部能力没有作为本次额外实验启用。
