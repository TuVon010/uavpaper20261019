# 2026-10-21 画图与复现定稿使用说明

这次整理把已经完成的seed17主实验与参数敏感性实验集中为一套可画图、可筛选展示算法、可另开新实验复现的项目。没有重新训练、修改模型、修改物理场景、改变奖励或重新选择best。本版只在外层增加画图、核验、复现入口和操作说明。

## 1. 保留的正式实验

当前`results/`保留`seed17_sensitivity_20261020_01`整套数据。它含18套唯一参数配置、每套8种方法，共144个方法–配置实验，其中108组为从零训练的强化学习方法，36组为规则基线。每个训练组均1000个60时隙episode，合计108000行逐轮记录。

主场景为3架UAV、20个用户。四条参数扫描为用户数、平均任务数据量、单UAV算力、单UAV带宽。四轴共20个显示点；用户数20、CPU10GHz、带宽10MHz复用同一主场景。因此不是20套独立配置，也不重复计为三次独立主实验。参数表、模型、方法及协议分别见已有系统模型、方法、参数与seed17实验说明。

任务大小的均值单位为Mbit，扫描使用`U[0.4μ,1.6μ]`，主场景仍保留`U[0.5,2]Mbit`。本轮这些扫描是**参数敏感性实验**；它们并不是拆除AR、延续价值、降噪或学习率衰减模块的算法组件消融。

历史seed1批次及其冻结实现移到当前项目外的历史归档，保留可恢复数据和归档记录；它们不参与本版图表，也不与seed17结果拼接。具体两端归档位置以本次定稿的整理记录为准，不应把项目内未再显示理解为已经永久删除。

`priority_mec/`物理环境、关联与KKT求解、强化学习更新实现保持原版本，源码指纹仍为`3ef6b15c31a7de84f7ce1fb64ee1e70f71b252e8ee7db35e05766d1db35ca870`。原完整运行库位于`frozen/seed17_sensitivity_20261020_01`，不能直接在冻结目录调参。根目录的新文档与画图工具不要求篡改原冻结README或原验证文件。

学习方法保留`episodes.csv`、`validation.csv`、`updates.jsonl`、`best.pt`、`last.pt`、`best_checkpoints/`、`evaluation_best/`与`evaluation_last/`；规则基线直接保留`evaluation/`，没有伪造训练过程或模型文件。评估目录内有逐episode汇总及逐帧任务、动作和轨迹。原结果目录下已有`plots/`也是归档原件；本次新图另放`figures/`，不覆盖这些原图。

新图位于各套件及各组结果的`figures/`目录；总入口为`results/seed17_sensitivity_20261020_01/figures/paper/`。其中包括奖励随episode变化、三指标性能柱状图、四轴三指标折线图以及轨迹图，并保留PNG预览、可编辑SVG/PDF和源数据表。具体文件名和生成命令以画图说明及该目录索引为准。

`configs/figures.json`控制显示方法、名称、顺序、颜色、线型、标记、输出格式与平滑窗口。例如把`hybrid_ppo_ar05`的`enabled`设为`false`，重新运行绘图即可隐藏它；不需要删模型或重训。若只画临时子集，优先使用绘图命令提供的方法筛选参数，并为新图设置独立输出tag。原始结果不会因为展示列表变化而改变。

## 4. 三个主指标怎么读

| 指标 | 字段 | 单位及定义 |
|---|---|---|
| 平均时延成本J | `weighted_delay_mean` | 无量纲；每槽`(1/N)ΣT_i/d_i`，再对时隙及评估episode平均 |
| 平均任务时延 | `mean_delay_s` | 秒；实际完成时间的算术平均 |
| UAV总能耗 | `total_energy_j` | J；单episode三架UAV推进与计算总和，图可除1000显示kJ |

每架UAV预算为12000J，能量可行要求三架分别达标。三机总能量低于36000J并不能保证每机均不超预算。图上应同时查看能量可行比例；时延更低但超预算不能写成所有约束下更优。

训练奖励直接使用日志中的完整episode return，包括既定目标和罚项。它不是仅把J取负。因此J下降而碰撞或预算罚增加时，奖励可能变差。MA25等平滑只是单次训练曲线的可读性辅助，不产生新的样本、置信区间或收敛证明。浅色原始曲线仍须与平滑曲线一起理解。

## 5. best、last和配对评估

best沿用原验证集episode20000–20002的`feasible_return`规则，last为训练末端60000步模型。本次整理分别绘图，不用最终评估重新选best，也不因last某项更好而替换best。规则基线没有两个模型，其best/last表格视图会重复同一次固定评估，不是两次独立实验。

每组最终评估是场景主seed17下的10个连续episode30000–30009。指定主场景单图是其中episode30000；它与10场景均值图不是同一统计量。训练seed也固定17，所以这并不是10次独立训练，更不是20个不同训练种子。能量可行10/10指10个评估episode全部可行。

同一case各方法使用相同外生任务、移动与信道输入，已核对完整场景和已保存逐帧哈希；CPU/带宽扫描与main的外生场景一致。跨用户数或数据范围时不要求整个场景哈希相同。用户数改变可共享随机前缀、数据改变可共享分位，但实际输入随扫描因素变化。

seed17是先前看过20场景比较后由用户选定的开发主场景。预留episode50000起测试未使用。本轮证据可支持此开发协议下的对比与敏感性趋势；不能据一个训练种子宣称跨训练种子的统计显著性、可靠收敛或所有物理场景下普遍最优。

## 6. 查看、重新画图与自行训练

先按画图说明运行Python/matplotlib脚本。仅重画不会调用训练或求解器，不修改评估，不改变模型选择。要重跑既有某case某方法，用[重新运行说明](15_rerun_experiments.md)的`tools/reproduce_suite.py`：默认预览，显式`--execute`才启动新tag。要改参数做新试验，改工作区配置副本，通过真实验证后使用新tag，不动旧计划和冻结库。

本次整理不继续自动优化算法。服务器和本地同步的是相同源码、原始结果、绘图配置、图像与文档。服务器进程是否运行仍以实际进程和对应新任务状态为准；本版的历史`suite.done`只能证明已完成的原seed17套件。

## 7. 定稿核验

外层核验器为`tools/verify_plot_release.py`，`tools/verify_release.py`现在也转发到该入口；旧核验脚本原件保存在源码备份包。新清单`MANIFEST.json`保存本版受管理文件的相对路径、字节数和SHA256；新增工具只读核对，不重画、不重训、不写新的通过标记。

```powershell
python tools/verify_plot_release.py --project .
python tools/verify_plot_release.py --project . --full-data
```

默认检查新定稿清单及图像清单；`--full-data`还流式核对`evidence/seed17_final_archive_manifest.json`记录的原始7368个文件，约17.1GB，耗时取决于磁盘。只有`passed=true`才表示此次检查通过。人为改了展示配置或重新生成图后，旧清单出现差异是预期的版本变化，应保存为新的展示输出/新定稿并记录新清单，不把差异静默忽略。

原始数据完整性由归档SHA、原始文件清单及独立核验记录支持；外层清单不能替代研究结果的科学有效性，也不把单训练种子图像变成统计显著性证据。
