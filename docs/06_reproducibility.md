## 2. 目录和字段

| 位置 | 用途 |
|---|---|
| run.py | 训练、评估、恢复、绘图、对照及面板统一入口 |
| configs/environment.json | 默认停服宽场景；物理、奖励、求解参数 |
| configs/common.json | 默认1000episode训练和原best/last评估协议 |
| configs/experiments/ | 8个recipe，各组可独立调训练参数 |
| priority_mec/ | 场景、信道、安全、环境、关联/KKT、RL、日志及图表共享实现 |
| tools/evaluate_seed20.py | 固定原best、原冻结实现和种子1–20评估工具 |
| tools/report_seed20.py | 由种子JSON重新整理配对表与审计 |
| tests/ | 回归、恢复、数学/物理和输出检查 |
| frozen/ | 已训练检查点的严格兼容运行实现 |
| results/ | 保留训练/评估原始结果，不由调参覆盖 |

每个学习组：

- `episodes.csv`：每完成一个episode一行，含回报、J、秒级时延、完成率、三机能量、罚项、停服及哈希。`end_step`是全局采样步，不是本episode槽数。
- `updates.jsonl`：每次网络更新的损失、KL、AR/探索尺度、学习率等。不同算法loss不能直接比大小。
- `validation.csv`：固定3场景随步数变化的验证指标，与带探索噪声的训练回报分开阅读。
- `best.pt`、`last.pt`和best历史：原选模型及完整恢复状态；best不能用作恢复点替代last。
- `effective_*.json`、`experiment.json`、`manifest.json`：实际环境、训练/评估协议、算法结构、设备与源码。
- `evaluation_best/`、`evaluation_last/`：原10episode的summary、episodes.csv与逐槽轨迹JSONL。基线使用 `evaluation/`。
- `plots/`：每回合曲线、验证曲线、能耗、best与last轨迹。
- `status.json`、`job.done`：步骤和完成记录；整批另有campaign.done。

逐槽轨迹包含槽首/槽末UAV位置、用户位置、请求/执行速度、关联、带宽、CPU、时延、能量、服务掩码、安全修正与卫星链路。`raw_delay_s`/无效掩码用于区别真实长尾和失败代理。训练 `train.csv`只在log_frames=true时生成，默认不生成不代表episode训练日志缺失。

## 3. 指标解释

`weighted_delay_mean`是无量纲J的episode均值；`mean_delay_s`以秒计。奖励中的J额外乘5，而CSV的J不乘5。`total_energy_j`是三机总和，预算可行逐机比较12000J。

`fully_feasible`要求电池与任务期限均满足；请求安全另看碰撞/越界计数。执行位置经过安全修正，不应将“碰撞请求帧”描述为发生了实际碰撞。停服比例分母为60×3个UAV时隙，不能与“任一机停服的时隙比例”混淆。第60槽末超预算与真正出现停服槽是两种事件。

## 4. 随机流和配对

训练种子与场景主种子为1。场景生成由主种子、episode和frame索引确定；同一索引下，任务/移动/衰落基础随机数组相同，不同时隙任务不同。策略不同导致UAV位置和实际信道增益不同，这是轨迹决策的结果，不是配对失败。

纯RL类别路由使用独立键控随机流；可选采样策略评估使用独立policy_seed=1生成器，跨episode连续，不消费训练随机状态。20种子协议固定为主种子1–20，各运行episode 30000；seed1也不等于复用训练episode。

新20种子目录保留160个种子输入结果、request.json、各组状态与job.done，以及汇总CSV、REPORT、pairing_audit.json。配对审计核对相同环境、逐场景/逐帧外生哈希和固定检查点SHA256，不根据好坏剔除场景。

## 5. 再次运行前检查

1. 先看有效配置、训练来源摘要、检查点步数和完整完成标志；不要将训练完成当评估完成。
2. 本地与服务器逐文件核对源码、配置、工具和文档；保留结果清单与检查点摘要。mtime相同不代表内容相同。
3. 修改参数用新JSON/recipe和新tag；旧模型评估读取保存环境，不自动套用现在的默认JSON。
4. 修改源码后先回归和短训/恢复/评估验证；需要复现旧结果时用旧冻结代码，不放宽检查。
5. 不要对已完成目录重复启动；不完整结果先改名保留，不静默覆盖。服务器其他项目与环境不属于本工程清理范围。

原训练验证证据保存在根目录 `SERVER_SERVICE_CUTOFF_VALIDATION.json` 等定稿记录中；它们描述当时执行的验证，不能当作以后修改源码也已验证。当前整理不补造训练日志、轨迹或检查点，不把20场景标准差当20次训练的误差条。
